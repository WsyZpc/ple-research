## 选定 14 道留出题

1. 按四个学科分层选题，同时检查两组的任务类型、评分方式和运行成本分布。一个题目仅归入一个集合。
2. 在锁定名单前核对题目使用记录。根据某题的产物、失败轨迹或逐项评分改过规则、提示词、工作流或 Memory，就将该题计入进化侧。同一任务的近似变体尽量同侧，例如两道机房走线题。
3. 将最终的任务 ID、学科、所属集合、划分理由和数据版本存入仓库。留出题的输入在正式评测时提供，评分反馈在整批评测结束后用于分析。

## 两次冻结

| 时间 | 冻结内容 | 用途 |
| --- | --- | --- |
| 现在 | 保存基线配置与本周人工编排的 Git 提交、流程 JSON、Word、评分结果和运行记录。记录模型、题面版本、工具、评分器与预算。 | 建立可复跑的对照。景观题的本地原评分器成绩 **70/77** 和 P08 **13/20** 保存为本轮人工编排结果。后续修订与复评单独登记。 |
| 进化实验结束后、留出评测前 | 锁定 15/14 题名单、待测提交、原子能力实现、工作流模板、提示词、重试预算和起始 Memory，并记录裁判配置与数据版本。 | 用同一版本评测 14 道留出题。每道题从同一起始 Memory 开始，允许系统按既定规则在单题内迭代。 |

留出评测记录首轮通过率、最终得分、人工介入次数、耗时和 Token 消耗。若后续根据留出反馈改进系统，为新版本另开实验记录。
